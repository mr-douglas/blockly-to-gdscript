Show health with hearts

Objective. Store health in a variable and keep a row of heart icons in step with it.

One number, drawn as icons

The game keeps health as a single number. The HUD creates one TextureRect per heart in an HBoxContainer. Each time health changes, update_hearts() loops over the hearts. It shows a full heart while the index is less than health and an empty one after that. The data and the picture are kept separate, so changing MAX_HEALTH changes both.

func update_hearts() -> void:
    for i in hearts.get_child_count():
        var heart: TextureRect = hearts.get_child(i)
        heart.texture = HEART_FULL if i < health else HEART_EMPTY

Losing a heart

Touching a hazard or falling off the bottom of the screen now calls lose_heart() instead of respawning straight away. A tween fades the frog from red back to white so the player can see the hit. When health reaches zero, set_physics_process(false) stops the game loop.

if health > 0:
    respawn()
else:
    out_of_health()

Predict, change, and test

  1. Walk into the gap once, then into the spikes twice. Predict the hearts after each hit and what happens on the last one.
  2. Set MAX_HEALTH to 5 and run the game. Count the hearts before and after a hit.
  3. Swap HEART_FULL and HEART_EMPTY in update_hearts(). Explain what the row now shows.
Check the prediction

Each hit empties one heart from the right. The third hit stops the game and shows the message. With five hearts, five icons are made because the loop runs MAX_HEALTH times. Swapping the textures shows the hearts you have lost instead of the ones you have left.

Success criteria. The number of full hearts always matches health. Hazards and falls both cost a heart, and the game stops at zero.

Apply it to your project. Add a health variable and a function that draws it in your HUD. Call that function every time health changes, rather than changing the icons in several places.
