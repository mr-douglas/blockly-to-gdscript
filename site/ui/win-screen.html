Finish with a "You win" screen

Objective. Time the run and show the player’s results on a win screen, completing a game with a menu, health, points and an ending.

Time the run

run_time adds delta on every physics step. While the game is paused, _physics_process() does not run at all. That means time spent on the start menu is not counted.

func _physics_process(delta: float) -> void:
    run_time += delta
    super._physics_process(delta)

Fill in the panel, then show it

The exit already checks the coins before it completes the level. This lesson calls that version with super, then shows the win screen if the level is now complete. get_node() finds the message label by its path inside the panel. A format string puts the coins, hearts and time into the text. %.1f shows the time to one decimal place.

func win() -> void:
    var message: Label = win_panel.get_node("Column/Message")
    message.text = "Coins: %d\nHearts left: %d\nTime: %.1f seconds" % [coins, health, run_time]
    show_panel(win_panel)

Predict, change, and test

  1. Wait on the start menu for ten seconds, then play and win. Predict whether those ten seconds are included in the time.
  2. Reach the trophy with only two coins. Predict whether the win screen appears.
  3. Add a score to the message, for example coins × 100 + hearts × 50. Test it with a careful run and a careless one.
Check the prediction

Time on the menu is not counted because physics does not run while the game is paused. With two coins the exit stays locked, so completed stays false and win() is not called. The score line needs one more %d and one more value in the array.

Success criteria. The game has a start menu, a points display, hearts, a game over screen and a win screen. Each screen’s button works, and the results shown match the run.

Apply it to your project. Add a win condition and an end screen to your own game. Show at least two values the player earned. Then test a winning run, a losing run and a restart from each screen.
