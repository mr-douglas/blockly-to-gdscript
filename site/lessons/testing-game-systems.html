Testing game systems

Learning objective. Choose test inputs, predict the expected results, and compare them with actual results.

Read the example

GDScript

extends Node

func can_finish(coins: int) -> bool:
    return coins >= 3

func _ready():
    print(can_finish(4) == true)
    print(can_finish(3) == true)
    print(can_finish(-1) == false)
  • Computer science. A test case pairs an input with an expected result. A boundary is where the outcome changes, so test just below, at, and above it.
  • GDScript. Use == to compare an actual result with the expected result. A test printing true means the two values matched.
  • Godot. Test a rule in a small script before relying on it during play. Add labels to distinguish cases when a test fails.

Predict the output

The rule needs at least 3 coins. Which test exposes the wrong comparison?

extends Node

func can_finish(coins: int) -> bool:
    return coins > 3

func _ready():
    print(can_finish(4) == true)
    print(can_finish(3) == true)
    print(can_finish(-1) == false)
Check the prediction

Only the boundary test fails. It prints true, false, true.

Debugging task · Use the right expectation

A negative coin count cannot finish the level. Fix the expected result.

func can_finish(coins: int) -> bool:

func _ready():
    print(can_finish(-1) == true)

Independent task · Test inventory slots

For a three-slot inventory, write tests for an ordinary valid slot, the last valid slot and the first slot outside the array. Also test slot 0 in an empty inventory.

extends Node

func valid_slot(index: int, size: int) -> bool:
    return index >= 0 and index < size

func _ready():

Success criteria. All four checks print true. Your invalid inputs include an index equal to the size and a slot in an empty inventory.
