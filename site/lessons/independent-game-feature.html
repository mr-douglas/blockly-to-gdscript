Independent PBL game feature

Learning objective. Build a substantial game feature in GDScript and use tests to explain your design decisions.

Read the example

GDScript

extends Node

var coins = 5
var stock = [{"name": "Map", "price": 5}]
var inventory: Array[String] = []

func buy(slot: int) -> bool:
    if slot < 0 or slot >= stock.size():
        return false
    var price: int = stock[slot]["price"]
    if coins < price:
        return false
    coins -= price
    inventory.append(stock[slot]["name"])
    stock.remove_at(slot)
    return true

func _ready():
    print(buy(0))
    print(coins)
  • Computer science. An algorithm is a sequence of steps that solves a problem. Define what your feature should do, including what it should do when given invalid input.
  • GDScript. Use meaningful variables, a data structure, selection and at least one reusable function that takes an input or returns a result. Use a loop where the feature repeats work.
  • Godot. This shop is one example. Build your own inventory, dialogue, scoring, enemies, map generation, combat, quests, difficulty, save data or menu feature.

Predict the output

A player has exactly 5 coins. What is printed, and what changes if they try to buy the same slot again?

Check the prediction

It prints true, false, then 0. The first purchase spends the coins and removes the stock entry. The second call is rejected because the slot no longer exists.

Apply it to your project

Move the tested code into your own Godot game. Connect it to a real game action, run the scene and repeat your checks during play. Keep the test inputs, expected results and actual results as evidence. Godot editor setup

Project checklist

  • Use meaningful variables and a data structure such as an array or dictionary.
  • Use selection for a game decision and iteration wherever the feature needs repeated work.
  • Use at least one reusable function with parameters or a return value.
  • Validate an input before changing the game state. Explain how invalid input is handled.
  • Record a normal, boundary and invalid test with expected and actual results.
  • Use readable GDScript with clear names and consistent indentation.
  • Explain your algorithm step by step and justify at least one design decision using your tests.

Share the working feature, its GDScript, your test results and your explanation.
